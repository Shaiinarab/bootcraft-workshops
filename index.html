سه ایستگاه؛ یک مهارت واقعی.

02 / WHAT YOU WILL ACTUALLY LEARN

از مفهوم تا دست‌به‌آچار شدن.

هدف، حفظ‌کردن اسم پارتیشن‌ها نیست. دانشجو باید بتواند زنجیره بوت را توضیح دهد، طرح دیسک را بخواند، نصب را با احتیاط اجرا کند و مسیر عیب‌یابی را انتخاب کند.

BIOS / UEFIGPT / MBRNTFS / EXT4ESP / MSRGRUB 2WINRE
01

Firmware و زنجیره راه‌اندازی

POST، نقش UEFI و BIOS، ورودی‌های NVRAM، Secure Boot، TPM 2.0، ACPI و تفاوت انتخاب Boot Device با Boot Manager.

FIRMWARE → BOOT MANAGER
02

دیسک، جدول پارتیشن و فایل‌سیستم

مقایسه GPT و MBR، پارتیشن EFI System Partition، Recovery و MSR، مفاهیم NTFS، FAT32، ext4 و Btrfs و اثر فرمت‌کردن بر داده‌ها.

GPT · ESP · NTFS · EXT4
03

رسانه نصب و محیط زنده

تفاوت ISO و فایل ایمیج، ساخت USB قابل بوت، بررسی UEFI boot، اجرای Live Session و تشخیص دیسک‌ها بدون تغییر ناخواسته.

ISO → USB → LIVE ENVIRONMENT
04

نصب ویندوز و لینوکس

نیازمندی‌های پشتیبانی‌شده Windows 11، نصب توزیع لینوکس، درایورها، Secure Boot، BitLocker و رمزگذاری دستگاه، و منطق Dual Boot.

INSTALL → CONFIGURE → VERIFY
05

بازیابی و عیب‌یابی نظام‌مند

Boot order، WinRE، ابزارهای بازیابی بوت، بررسی فایل‌سیستم و دیسک، خواندن پیام خطا، ثبت تغییرات و تصمیم‌گیری درباره Restore یا Reinstall.

OBSERVE → HYPOTHESIZE → TEST → RECOVER

04 / SAFETY IS PART OF THE CURRICULUM

هیچ داده‌ای ارزش یک نمایش قهرمانانه را ندارد.

کارگاه نصب سیستم‌عامل بدون سیاست ایمنی، فقط یک روش پرهزینه برای تولید لپ‌تاپ خراب است.

LAB POLICY / NON-NEGOTIABLE

دستگاه شخصی؟ دست نزن.

تمام عملیات تغییردهنده دیسک فقط روی لپ‌تاپ‌های متعلق به دانشگاه، SSD آزمایشگاهی جداشدنی یا ماشین مجازی انجام می‌شود. دستگاه شخصی دانشجو فقط برای مشاهده و تحلیل، بدون تغییر پارتیشن یا Firmware قابل استفاده است.

01
بکاپ و مالکیت روشنپیش از هر نصب، مالک دستگاه، وضعیت داده و مجوز پاک‌سازی باید مشخص باشد.
02
BitLocker و Recovery Keyوضعیت رمزگذاری و کلید بازیابی پیش از تغییر Firmware یا Boot بررسی می‌شود؛ کلیدها در گزارش عمومی ذخیره نمی‌شوند.
03
Secure Boot را کورکورانه خاموش نکنتنظیمات Firmware فقط در سناریوی آموزشی مصوب و با ثبت وضعیت اولیه تغییر می‌کند.
04
بازگشت به وضعیت پایههر دستگاه بعد از تمرین با Image استاندارد پاک‌سازی و دوباره آماده تحویل می‌شود.
05
نصب فقط روی هدف تأییدشدهپیش از هر عملیات نوشتن روی دیسک، شناسه و ظرفیت دیسک با چک‌لیست دو نفره تطبیق داده می‌شود.

قانون طلایی: اول Snapshot، بعد آزمایش.

در نبود تجهیزات بازگشت‌پذیر، تمرین به شبیه‌سازی یا ماشین مجازی منتقل می‌شود.

ترکیب پیشنهادی هر گروه چطور است؟

برای هر ۲ تا ۳ دانشجو یک دستگاه آزمایشگاهی مناسب است؛ یک مدرس اصلی، یک دستیار فنی و یک مسئول تجهیزات/ایمنی برای گروه حدود ۱۲ تا ۱۶ نفر پیشنهاد می‌شود.

آیا شرکت‌کننده باید لینوکس بلد باشد؟

خیر. آشنایی پایه با فایل‌ها و پوشه‌ها کافی است. مفاهیم تخصصی در کارگاه اول معرفی می‌شوند؛ کار با ترمینال در حد نیاز آموزش داده می‌شود.

چه چیزهایی باید قبل از روز کارگاه آماده باشند؟

لپ‌تاپ‌های دانشگاهی، SSD یا دیسک‌های آزمایشگاهی، USBهای نصب، Imageهای تأییدشده، آداپتور و هاب، نسخه پشتیبان، چک‌لیست تحویل/بازگردانی و یک سناریوی VM جایگزین.

چطور یادگیری سنجیده می‌شود؟

یک آزمون تشخیصی کوتاه، چک‌لیست مشاهده عملکرد در هر ایستگاه، گزارش نهایی گروه و آزمون پس از کارگاه. موفقیت با توانایی توضیح و اجرای ایمن سنجیده می‌شود، نه فقط نصب موفق.

این کارگاه جایگزین دوره تخصصی ادمین سیستم است؟

نه. این دوره یک ورودی عملی و قابل لمس به معماری بوت و نصب سیستم‌عامل است؛ نه آموزش جامع مدیریت سازمانی، امنیت پیشرفته یا بازیابی تخصصی داده.
