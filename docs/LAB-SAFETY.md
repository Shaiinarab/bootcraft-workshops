# سیاست ایمنی آزمایشگاه BOOTCRAFT

این سند پیش‌شرط اجرای هر فعالیت عملی است. مسئول کارگاه حق دارد هر تمرینی را که پیش‌شرط ایمنی آن فراهم نیست متوقف یا به VM منتقل کند.

## اصل صفر: دستگاه شخصی شرکت‌کننده هدف نصب نیست

هیچ نصب سیستم‌عامل، پارتیشن‌بندی، فرمت، پاک‌سازی، دست‌کاری Bootloader یا تغییر تنظیم Firmware روی لپ‌تاپ شخصی شرکت‌کننده انجام نمی‌شود. دستگاه شخصی فقط برای مشاهده، یادداشت‌برداری یا نمایش بدون تغییر قابل استفاده است.

## سلسله‌مراتب محیط تمرین

۱. ماشین مجازی Disposable با Snapshot و دیسک مجازی قابل حذف  
۲. SSD آزمایشگاهی جداشدنی و اختصاصی  
۳. لپ‌تاپ متعلق به دانشگاه که برای پاک‌سازی و بازگردانی آماده شده است

اگر امکان بازگشت مطمئن به وضعیت پایه وجود ندارد، تمرین نوشتنی اجرا نمی‌شود.

## چک‌لیست پیش از شروع

### مالکیت و مجوز
- [ ] مالکیت دانشگاهی دستگاه یا دیسک هدف تأیید شده است.
- [ ] مجوز مکتوب برای نصب/پاک‌سازی و مسئول تأیید مشخص است.
- [ ] شماره دارایی یا شناسه داخلی دستگاه ثبت شده است.
- [ ] دستگاه شخصی دانشجویان از عملیات نوشتن حذف شده است.

### داده و رمزگذاری
- [ ] هر داده موردنیاز، پشتیبان‌گیری و بازیابی نمونه‌ای آن بررسی شده است.
- [ ] وضعیت BitLocker یا Device Encryption بررسی شده است.
- [ ] Recovery Key در صورت نیاز توسط مسئول مجاز در مسیر امن خارج از مخزن و خارج از گزارش عمومی نگهداری می‌شود.
- [ ] هیچ Recovery Key، رمز عبور یا اطلاعات شخصی در اسکرین‌شات یا گزارش عمومی ثبت نمی‌شود.

### رسانه و دیسک
- [ ] Image سیستم‌عامل از منبع معتبر دریافت شده است.
- [ ] صحت فایل با سازوکار رسمی ناشر، در صورت ارائه، بررسی شده است.
- [ ] ظرفیت و شناسه دیسک هدف توسط اپراتور و ناظر دوم تطبیق داده شده است.
- [ ] USB نصب و دیسک آزمایشگاهی با برچسب مشخص شده‌اند.
- [ ] آداپتور برق و سلامت کابل‌ها بررسی شده‌اند.

### مسیر بازگشت
- [ ] Image پایه یا Snapshot موجود است.
- [ ] فرآیند Restore روی حداقل یک دستگاه آزمایشی قبلاً تست شده است.
- [ ] زمان و مسئول بازگردانی مشخص است.
- [ ] رسانه بازیابی و راهنمای بازگردانی در دسترس است.

## چک‌لیست پیش از هر عملیات تغییر دیسک

- [ ] عملیات دقیق به زبان ساده برای گروه توضیح داده شده است.
- [ ] دیسک هدف از روی نام، ظرفیت و شناسه دوباره تأیید شده است.
- [ ] هیچ دیسک اشتباهی یا رسانه USB حاوی داده موردنیاز انتخاب نشده است.
- [ ] ناظر دوم تأیید کرده است.
- [ ] امکان توقف و بازیابی وجود دارد.

**قاعده دو نفره:** هیچ عملیات Delete، Format، Write یا Restore بدون تأیید اپراتور و ناظر دوم اجرا نمی‌شود.

## Firmware و Secure Boot

- تنظیم Firmware فقط در سناریوی مشخص و با ثبت وضعیت اولیه مجاز است.
- گزینه‌های ناشناخته، Firmware update و Reset to defaults در تمرین عادی ممنوع‌اند.
- Secure Boot به‌صورت پیش‌فرض خاموش نمی‌شود. هر تغییر باید ضرورت آموزشی، مجوز، پیامد و مسیر بازگشت مشخص داشته باشد.
- تغییرات مرتبط با TPM و Secure Boot ممکن است باعث درخواست Recovery Key یا تغییر رفتار بوت شوند؛ پیش از هر تغییر، وضعیت رمزگذاری و Recovery بررسی می‌شود.

## شرایط توقف فوری

تمرین باید متوقف شود اگر:
- دیسک هدف با برچسب و ظرفیت مورد انتظار تطابق ندارد.
- داده‌ای مشاهده می‌شود که مالکیت یا نیاز به نگهداری آن مشخص نیست.
- Recovery Key یا مسیر بازیابی در دسترس نیست.
- دستگاه داغی غیرعادی، صدای مکانیکی یا خطای سخت‌افزاری نشان می‌دهد.
- برق، کابل، آداپتور یا اتصال USB ناپایدار است.
- شرکت‌کننده درباره پیامد یک عملیات نوشتن مطمئن نیست.
- عملیات از سناریوی مصوب فراتر می‌رود.

## حفاظت از حریم خصوصی

- از نام کامل، ایمیل، شماره دانشجویی، کلید بازیابی، رمز عبور یا فایل شخصی تصویربرداری نشود.
- گزارش‌ها با شناسه گروه یا کد دستگاه ثبت شوند.
- تصاویر آموزشی پیش از انتشار بازبینی و پاک‌سازی شوند.
- اطلاعات دستگاه‌ها فقط تا زمان لازم برای تحویل و بازگردانی نگهداری شود.

## پایان کارگاه و بازگردانی

- [ ] سیستم‌عامل و دیسک به وضعیت استاندارد مصوب بازگردانده شده‌اند.
- [ ] USBها شمارش و از دستگاه‌ها جدا شده‌اند.
- [ ] Boot Order و تنظیم Firmware در صورت تغییر به وضعیت ثبت‌شده بازگشته‌اند.
- [ ] BitLocker و وضعیت حفاظت دستگاه دوباره بررسی شده‌اند.
- [ ] دیسک‌ها و دستگاه‌ها از نظر عملکرد بوت تست شده‌اند.
- [ ] فرم تحویل تجهیزات توسط مسئول ثبت شده است.

**ایمنی بخشی از مهارت فنی است.** هدف این نیست که دانشجو فقط بتواند نصب را تمام کند؛ باید بداند چه زمانی نباید دکمه تأیید را فشار دهد.
